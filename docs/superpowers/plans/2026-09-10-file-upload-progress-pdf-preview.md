## 1. 已核对的现状

1. `F/src/api/file.js` 已配置 `onUploadProgress`，按 loaded / total 上报百分比；total 不存在时直接返回，页面可能没有变化。上传超时已经单独设为 30 分钟，不要误改回普通请求的 15 秒。
2. `F/src/views/files/FileList.vue` 已有 `a-progress`，`handleCustomUpload` 成功后也已调用 `fetchFiles()`。本次不是简单补一个进度组件或重复加刷新调用。
3. 当前只有文件名和百分比，没有区分传输、服务器处理、成功和失败；传输到 100% 就可能显示绿色完成，但标题仍是“正在上传”。最终状态在 finally 中立即移除。
4. `B/apps/upload/views.py` 上传接口会同步执行媒体处理、存储与数据库写入。浏览器发送完请求体不等于文件已可用。截图中的状态矛盾与此实现相符，实际卡顿位置仍需限速联调确认。
5. `fetchFiles()` 自己捕获异常，上传流程无法可靠区分“上传失败”和“上传成功但列表刷新失败”；现有页码、筛选也可能让新文件不在当前列表中。
6. 预览列只处理图片、音频和视频，其余文件显示下载。普通下载接口会增加下载次数，不能直接拿来做 PDF 预览。
7. `_file_response()` 的可内联类型不包含 PDF，即使调用 `as_attachment=False`，PDF 仍会被改成下载响应。因此新增预览动作不能只复用这个调用就宣称完成。
8. 上传入口有顶部按钮和拖拽区域，`multiple=false` 只限制单次选文件，不能防止两个入口交叉上传。

## 2. 交互方案与边界

### 上传：真实进度与自动更新

“上传完成自动刷新页面”落实为：服务器确认成功后，自动重新获取文件列表及页面相关统计，不整页 reload；保留用户筛选和操作上下文。普通无筛选场景回第一页，按最新上传排序显示新文件。

| 阶段 | 显示内容 | 进度和交互 |
| --- | --- | --- |
| 上传中 | 文件名、百分比、已发送 / 总传输量 | 蓝色进度；没有总量时显示不定进度及已发送量，不伪造百分比 |
| 服务器处理中 | “传输完成，服务器处理中” | 中性活动状态；不显示绿色成功，不虚构处理百分比 |
| 上传成功 | “上传成功”及文件名 | 绿色完成，自动更新列表；成功提示至少保留 3 秒 |
| 上传失败 | 具体可理解的错误、重试操作 | 红色状态保留到用户操作，不在 finally 中清掉 |
| 列表刷新失败 | “文件已上传，列表刷新失败” | 提供“刷新列表”，只能重试查询，不重新上传文件 |

- 有可靠 total 时上传百分比使用真实事件计算；四舍五入不得提前完成，未收到业务成功前不得显示成功勾号。
- 发送尚未完成时可将显示值限制在 99%；loaded 达到 total 后切换“服务器处理中”。极小文件可能直接成功，不人为拖慢上传来表演进度。
- 传输量可能含 multipart 开销，文案使用“已发送 / 总传输量”，不要与文件大小混为同一口径。不展示估算不准的剩余秒数。
- 上传期间同步禁用两个上传入口，保留浏览列表能力；本轮保持单文件上传，不新增队列、分片或断点续传。
- 保留筛选时，先刷新该筛选的第一页。如果新文件不在返回结果中，成功区域保留文件名和“查看刚上传文件”操作；点击后清除筛选并查询第一页。不要静默清空筛选。
- 刷新期间保留已有列表，使用局部 loading；刷新失败保留旧数据并明确提示其未更新。不要把暂时查询失败显示成“文件总数 0”。
- 超时或断网可能发生在服务器已经保存之后。此时提示“上传结果暂未确认，请先刷新列表确认”，不自动重发 POST。确认未成功后用户才能主动重新选择文件上传。
- 成功、失败回调各只调用一次；可选回调不存在时不得报错。用户切换页面后不继续写入已卸载组件，取消客户端等待不声称服务器已回滚。

### PDF：页面内阅读

选择 PDF.js 页面内预览。原生 iframe 实现短，但手机体验和带 Bearer 鉴权的私有文件处理不统一；本轮使用现有认证请求获取二进制数据，再交给 PDF.js。文件不发送到第三方在线预览服务。

- PDF 行的预览列显示文件图标及“预览”；原有“下载、复制链接、删除”保持原功能。其他文档继续下载，图片、视频、音频不受影响。
- 优先依据 `content_type=application/pdf` 判断；历史 MIME 缺失或为通用二进制类型时，允许以不区分大小写的 `.pdf` 扩展名显示入口。实际内容由服务端检查及 PDF 解析再次验证。
- 桌面使用居中预览弹窗，宽度不超过 1120px 且不超视口，高度约 85vh；手机使用全屏或接近全屏弹层。
- 顶栏显示文件名、下载、关闭；工具栏提供上一页、下一页、当前页 / 总页数、缩放、适应宽度。手机允许工具栏分行，按钮不挤到屏幕外。
- 默认适应宽度，仅渲染当前页；长页在预览内容区滚动，放大后允许内容区横向滚动，不带动整个后台页面溢出。
- 加载时显示文件获取进度；有总量才显示百分比。下载完毕后显示“正在解析 PDF”，首张页面完成渲染才显示阅读内容。
- 提供文本层以支持选择、复制和基本可访问性；不启用 PDF 内脚本、附件执行和不必要的交互插件。导航控件有可访问名称、键盘焦点，关闭后焦点回到预览入口。
- 首版采用完整二进制获取，不声称支持 Range、边下边读或断点续传。预览上限设为 **50 MiB**，覆盖 25 MB 示例；超限明确提示并保留下载。该限制仅影响在线预览，不改变现有上传上限。
- 加密 PDF 首版提示“该 PDF 需要密码，请下载后查看”；损坏、空文件、权限不足、文件不存在、存储不可用分别给出明确状态，不显示空白弹窗。
- 关闭、换文件、快速切页时取消过时请求和渲染任务，销毁 PDF 文档/worker 使用资源并清理 canvas；连续打开不能持续累积内存。限制 canvas 像素规模，手机避免过高设备像素比造成内存峰值。
