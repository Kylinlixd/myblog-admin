# 个人资料页重排：设计建议与 Luna 执行说明

状态：已执行。本轮完成个人资料页重排、收窄表单宽度、交互回归测试和桌面/移动实际渲染检查；待提交并发布线上版本。

## 目标与已确认原因

沿用现有后台蓝色、浅灰背景、白色圆角卡片，重新组织个人资料页面，使身份、资料编辑和密码操作有稳定对齐关系。用户已拒绝浏览器设计辅助，不再要求其选择原型工具或重复确认方案。

代码核对：`src/views/user/Profile.vue` 两个表单仍设置 label-col=4、wrapper-col=18；桌面昵称/邮箱又使用 nth-of-type 和 inline-flex 缩成半宽。每个半宽字段内部继续受到列宽限制，导致输入框短、标签错位，且与用户名/简介不对齐。修复应替换这套布局，而不是追加宽度覆盖。

上一轮身份分栏、统一默认头像、视觉验收没有完整落地。本说明以当前代码和截图为准；本轮已补齐这些缺口。

## 视觉规格

| 项目 | 建议 |
| --- | --- |
| 页面宽度 | 最大 960px，宽度不超过后台内容区 |
| 页面标题 | 28px、字重 700；副标题 14px；标题区与首卡间距 24px |
| 英文眉题 | 可保留，10–11px、低强调；不扩大标题区高度 |
| 卡片 | 圆角 16px，1px 浅灰边框，复用现有轻阴影 |
| 卡片间距 | 20px |
| 卡片标题 | 16px、字重 600；内边距 20–24px；副说明允许自然换行 |
| 正文内边距 | 桌面 24px，手机 16px |
| 表单 | 标签 13–14px；标签到输入 8px；字段之间 20px |
| 输入框 | 单行高 40px、圆角 8px；不锁定整个表单高度 |
| 简介 | 最小高度 100px，允许纵向扩展，计数在右下 |
| 头像 | 80px；使用用户真实图片，缺失或加载失败才回退到蓝灰底文字 |
| 操作区 | 顶部间距 20px、细分割线；按钮高 40px、间距 10px |
| 主次按钮 | 次按钮在左、蓝色主按钮在右；上传头像使用次按钮 |

减少大片空白不能靠把字号和输入框缩小。背景沿用当前主题变量；使用颜色只突出主操作、焦点及错误。取消无意义的“可编辑”徽标，改为随状态变化的“已保存 / 有未保存修改”。没有修改时主按钮禁用，但提示要能解释原因。

## 头像与身份展示

- 身份区的昵称/用户名取已保存用户信息，表单是编辑副本；保存成功后身份区与顶部同步。
- 头像回退优先级：已保存昵称首字 → 用户名首字 → 通用人像。去除资料页硬编码默认头像图片的依赖，防止无头像时出现与用户无关的“Z”。
- 不改变真实上传图片的颜色；统一的蓝灰底仅用于回退头像。
- 角色从用户实际 role 读取，使用现有角色映射，不硬编码“管理员”或虚构在线状态。
- 上传区域显示“JPG / PNG，小于 2MB”“上传成功后立即生效”。上传中禁用按钮并展示状态，失败保留旧图。
- 保留现有上传成功同步 store 和 savedProfile.avatar 的逻辑；撤销文本不能回滚已保存头像。
- 顶部和资料页需要相同回退行为时，可抽取一个小型 UserAvatar 组件；不为此改造整个用户状态架构。

## 表单和密码行为

- 保留用户名编辑能力，提示“修改后请使用新用户名登录”；不要在视觉改造中擅自禁用字段。
- 字段错误就近显示，不只弹消息。辅助文字自动换行；不让错误信息覆盖按钮或下一个字段。
- 保存失败保留输入；提交中禁用重复提交；撤销修改恢复最近成功保存的文本并清除校验提示。
- 密码区使用已有密码规则和接口，保留 autocomplete、明文切换按钮；清空输入同时清除校验提示。
- 不增加没有后端能力支撑的邮箱验证、安全等级、设备退出成功等提示。

## 响应式布局

- 按页面实际可用宽度判断，避免只使用 viewport：后台侧栏展开时，内容区域会明显变窄。
- 内容宽度 >= 760px：身份/表单两列，昵称/邮箱两列。
- 内容宽度 < 760px：两张卡片内部均单列；身份区改为头像与摘要横排，上传说明换到下一行；密码规则置于密码字段上方。
- 内容宽度 < 520px：昵称/邮箱也变为单列；按钮保持文字可读，可等宽排列，不强制 fixed 悬浮。
- 优先使用容器查询，提供普通单列基础样式作为回退；长邮箱和昵称允许折行，所有网格子项设置 min-width:0。

## 文件与实现边界

主要修改 `src/views/user/Profile.vue` 的 template 和 scoped styles。

1. 删除两套 label-col/wrapper-col，两个表单改为 `layout="vertical"`。
2. 将头像上传从表单字段抽到身份 aside，资料表单保持在右栏。
3. 使用具名布局类（如 profile-layout、profile-identity、profile-fields、profile-field-pair），删除 nth-of-type 定位字段的规则。
4. 统一基本信息和密码区域的两列轨道；清理本文件不再使用的 profile-info/info-list 等旧样式。
5. 视需要调整 `src/layouts/DefaultLayout.vue` 的头像回退；保留顶部其他布局。
6. 沿用 `src/stores/user.js`、`src/api/auth.js` 现有协议。此次不修改后端、仪表盘或登录页。
7. 保留工作区其他未提交文件。尤其不要删除 `BlogHome 2.vue` 或其测试来让全量测试变绿。
