# 夜蓝数字花园 60 秒竖屏介绍片设计

## 目标

为 leexd.top 创作一支适合抖音发布的中文品牌介绍片。视频需要在前三秒建立“夜蓝数字花园”的视觉记忆，同时清晰呈现公开博客、移动端阅读、内容管理后台和持续构建理念。

成功标准：

- 成片时长控制在 58–60 秒。
- 输出 1080×1920、30 FPS、H.264 MP4，包含 AAC 立体声音轨。
- 手机正常观看距离下，标题、字幕和域名均清晰可读。
- 旁白、字幕、音乐、镜头动作完全同步。
- 画面忠于现有夜蓝视觉系统，不使用通用科技模板或与产品无关的素材。

## 创意方向

采用“电影感数字花园”方向：夜蓝星雾、克制网格、超大动态排版和具有景深的产品画面共同构成叙事。品牌情绪负责建立记忆，真实界面负责证明产品完整度。

视觉基调：

- 背景：#050A13 至 #081426 的深夜蓝。
- 主文字：#EEF4FF。
- 强调色：#7698FF 与少量青蓝光。
- 字体：优先使用本地中文无衬线字体，标题使用高字重，正文保持宽松字距。
- 核心元素：星雾、细网格、柔和光团、页面景深、遮罩揭示。
- 禁止元素：高频闪烁、花哨 3D 旋转、密集小卡片、不可读小字、通用霓虹赛博朋克装饰。

## 画面规格与安全区

- 画布：1080×1920。
- 帧率：30 FPS。
- 目标总帧数：1800 帧。
- 重要文字距左右边缘至少 80 px，距顶部至少 120 px。
- 字幕放在画面下部但避开抖音底部交互区，底边保留至少 260 px。
- 主标题不小于 96 px，重要辅助文字不小于 48 px，字幕不小于 44 px。
- 每个镜头只保留一个主要信息和一个辅助视觉。

## 六段式叙事

### 01. Hook：探索技术，无限可能（00:00–00:06）

- 黑场中的微光聚合成星雾和细网格。
- “探索技术 / 无限可能”两行超大标题以遮罩和纵向位移进入。
- 第一处低频冲击落在“无限可能”出现时。

### 02. The Idea：不是答案库，是一条路径（00:06–00:15）

- 博客首页像一扇门从远处靠近。
- 标题从“答案”切换为“问题、判断、修正、沉淀”。
- 页面保持可辨识，但不与旁白争夺注意力。

### 03. Explore：阅读、发现、连接（00:15–00:27）

- 真实公开首页、文章详情、分类和移动端画面连续穿梭。
- 镜头以平缓推近、轻微透视和遮罩切换为主。
- 展示阅读路径，不堆叠多个页面缩略图。

### 04. Build：持续构建，清晰管理（00:27–00:39）

- 仪表盘、统一列表、编辑器和移动交互依次出现。
- 关键指标使用大号数字，列表和按钮只作为辅助证据。
- 后台画面使用依据现有实现制作的高保真界面镜头，不展示虚构业务数据。

### 05. Principles：记录判断，不只答案（00:39–00:51）

- 三条原则随低频脉冲逐条出现：
  1. 从真实问题出发。
  2. 让知识彼此连接。
  3. 持续构建与复盘。
- 音乐在本段达到情绪最高点。

### 06. CTA：保持好奇，继续构建（00:51–01:00）

- 星点与网格向中心收束。
- “保持好奇 / 继续构建”进入后淡出。
- LEEXD.TOP 独立停留至少 4 秒，最后落入纯夜蓝黑场。

旁白使用年轻、沉稳的普通话声线，避免广告腔。按场景分别生成音频，使停顿和镜头时长可以精确控制。主方案使用 edge-tts 的 zh-CN-YunxiNeural 神经声线；不可用时使用 macOS Tingting 普通话系统声线作为确定性回退。

## 音乐、音效与混音

- 使用 FFmpeg 合成器生成原创 90 BPM 夜蓝氛围电子配乐，避免外部音乐授权风险。
- 编排包括低频脉冲、空气感铺底、玻璃质感合成器和末段抬升。
- 旁白期间音乐自动压低，句间适度恢复。
- 转场仅使用少量 whoosh、低频冲击和细微开关声。
- 音效不得覆盖辅音或影响旁白理解。
- 开头和结尾使用平滑音量曲线，禁止突兀截断。

## 字幕

- 所有字幕使用 Remotion Caption JSON 数据结构管理。
- 每屏最多两行，以语义短句切分，不逐字跳动。
- 当前重点词使用强调蓝，其他文字为白色。
- 字幕背景使用半透明深色软底，确保复杂画面上仍有足够对比度。
- 字幕时间根据最终旁白音频校准，不依赖估算时长。

## 素材策略

- 公开博客镜头优先来自 leexd.top 的实际桌面和移动端页面。
- 管理后台镜头依据现有 Vue 页面和夜蓝后台样式制作高保真演示画面。
- 品牌图形、星雾、网格和光团全部通过 Remotion、CSS 或 SVG 程序化生成。
- 不使用与产品无关的库存人物、办公场景或第三方品牌素材。
- 音乐为本项目原创生成；音效使用明确允许用于 Remotion 项目的资源。

## Remotion 架构

视频工程与博客应用隔离，放在工作区 **work/leexd-intro-video**，避免污染前后端依赖。

主要模块：

- **Root.tsx**：注册 1080×1920、30 FPS、1800 帧的组合及默认参数。
- **NightBlueIntro.tsx**：编排六个场景、全局音频、字幕和过渡。
- **scenes/**：每个场景一个组件，只负责单一叙事目标。
- **components/**：星雾背景、网格、标题揭示、界面镜头、字幕和域名收束。
- **data/script.ts**：旁白、场景时长、字幕和强调词的唯一数据源。
- **scripts/**：生成旁白、配乐与截图素材。
- **public/**：渲染所需的音频、截图和图像资源。

所有动画由 useCurrentFrame()、interpolate() 和显式缓动驱动。禁止 CSS transition、CSS animation 和 Tailwind 动画类。场景使用 TransitionSeries 编排，转场重叠帧数计入总时长。

## 数据流

1. 场景脚本定义旁白文本、场景 ID 和目标时长。
2. 生成脚本按场景输出旁白音频。
3. 音频时长用于校准场景时长与 Caption JSON。
4. 页面截图和程序化视觉元素进入对应场景。
5. Remotion 组合统一渲染画面、旁白、音乐、音效和字幕。
6. FFmpeg/ffprobe 验证容器、时长、分辨率、帧率和音轨。
7. 最终 MP4 复制到工作区 outputs/ 作为用户交付件。

## 失败处理

- 页面截图失败时，保留程序化高保真界面作为回退，不中断整支视频。
- 神经 TTS 不可用时切换到本地系统普通话声线。
- 音频生成后检查文件存在、大小和持续时间，失败场景单独重试。
- 素材缺失时渲染前直接报错，不输出不完整成片。
- 所有网络素材在最终渲染前落地到 public/，保证渲染可重复。

## 验证与交付

- 对 3、12、21、33、45、56 秒的代表帧执行静帧渲染。
- 在正常尺寸下检查每帧的焦点、字幕可读性、安全区和元素重叠。
- 渲染低分辨率预览并检查六段节奏与旁白同步。
- 渲染最终 1080×1920 MP4。
- 使用 ffprobe 确认：58–60 秒、1080×1920、30 FPS、H.264 视频和 AAC 音轨。
- 抽取接触表检查全片色彩、镜头连续性和结尾域名停留。
- 最终交付 MP4；同时保留 Remotion 源工程，便于后续改文案或输出横屏版本。
