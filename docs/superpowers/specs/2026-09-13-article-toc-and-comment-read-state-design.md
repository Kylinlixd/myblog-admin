# 文章详情目录与评论未读基线设计

## 目标

在文章详情页增加性能稳定的右侧阅读目录，并把后台新评论提醒从浏览器本地计数迁移为按管理员账号保存的服务端已读基线。两部分都保持现有暖米色博客视觉、Markdown 代码块、评论展示和路由行为。

## 设计决策

- 目录来源于正文渲染后的 `h2`、`h3`、`h4`，不重复展示文章主标题。每个标题生成稳定、可访问的锚点 ID；重复标题追加序号。
- 桌面端目录位于文章正文右侧，使用 `position: sticky` 跟随阅读；当前标题通过 `IntersectionObserver` 更新高亮，滚动回退逻辑使用节流的 `requestAnimationFrame`，避免每个 scroll 事件逐个读取布局。
- 点击目录使用原生平滑滚动并保留键盘焦点语义；移动端用文章头部下方的折叠目录，尊重 `prefers-reduced-motion`。
- 未读评论以管理员账号的一行状态保存：`last_seen_comment_id`（加初始化标记与更新时间）。未读定义为当前账号有权查看、非本人、非已拒绝且主键大于已读基线的评论。
- 未读摘要接口只返回数量、最新有效评论 ID 和初始化状态；读取当前页成功渲染后，前端提交当前可见评论的最大 ID，后端使用单条 `UPDATE` 推进基线，天然幂等且不会把新增评论误标为已读。
- 保留旧 `CommentReadReceipt` 表和兼容读取一段时间，迁移脚本将历史状态压缩为账号基线后再由后续清理迁移删除，避免一次发布破坏现有数据。
- 仪表盘继续显示评论总数；红点/数字角标使用未读摘要，不再从 localStorage 推断新评论。

## 接口契约

`GET /api/comments/unread-summary/`

```json
{"code":200,"data":{"unread_count":2,"latest_comment_id":87,"initialized":true}}
```

`POST /api/comments/mark-read/`

```json
{"latest_comment_id":87}
```

服务端只允许基线向前推进，返回更新后的摘要；请求失败或当前页未渲染时，前端保留红点。

## 验收标准

1. 有正文标题的桌面文章详情显示右侧目录；滚动时一次只更新当前高亮，不产生明显抖动或横向溢出。
2. 目录按钮可键盘操作，点击后平滑定位；减少动画时直接定位。移动端目录可展开/收起。
3. 无标题文章不显示空目录，文章正文宽度自动回到单列。
4. 新评论在不同浏览器、刷新和重新登录后仍能被同一管理员看到提醒；另一个管理员拥有独立基线。
5. 阅读评论列表成功后只将已展示到的最大 ID 标记为已读，之后新增评论仍显示红点。
6. 仪表盘评论卡片数字仍是总评论数，未读提示独立显示；评论管理页面不出现重复的仪表盘红点逻辑。
7. 前端相关测试、后端迁移/接口测试和生产构建通过。
