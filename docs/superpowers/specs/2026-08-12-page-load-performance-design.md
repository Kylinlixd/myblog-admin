# 页面加载性能优化设计

日期：2026-08-12

## 目标

同时优化博客前台 `blog-web` 与管理后台 `blog-admin` 的页面加载性能，优先降低首屏 JavaScript、无效网络请求和媒体资源开销，不改变文章发布、文件上传、登录和路由权限行为。

## 范围

### 包含

- 两个前端项目的构建产物拆分与缓存策略。
- 首页、文章列表、文章详情和后台仪表盘的请求去重与按需请求。
- 图片、视频和非首屏媒体的懒加载、加载失败回退和优先级控制。
- Nginx 静态资源压缩、长期缓存与发布版本兼容。
- 构建体积、网络请求、浏览器首屏和关键路由回归验证。

### 不包含

- 不引入 CDN、SSR、预渲染或新的云服务。
- 不迁移数据库，不调整现有 API 字段和权限模型。
- 不改变现有 UI 视觉风格、编辑器能力和上传格式支持。
- 不对视频源文件做不可逆批量转码；媒体优化只处理加载策略和可选的服务端响应能力。

## 设计方案

### 1. 构建与资源加载

- 保留现有路由级懒加载，移除会造成非必要预加载的配置，避免用户只打开首页时下载后台和详情页代码。
- 为 Vue、React、路由、状态管理、Ant Design、图标和网络库建立稳定的 vendor chunk；业务页面保持路由级 chunk，减少跨版本缓存失效范围。
- 生产构建开启 gzip/Brotli 可用的服务器压缩，JavaScript、CSS、JSON 和 SVG 使用长期缓存；HTML 使用短缓存或不缓存。
- 保留资源 hash 和 `/assets/` 404 保护，发布时通过新资源 hash 配合 HTML 更新，避免旧 chunk 被错误返回为 HTML。

### 2. 请求与数据访问

- 对同一页面生命周期内的相同 GET 请求做轻量去重，避免组件挂载、路由切换和重试造成重复请求。
- 只在当前页面需要时请求分页数据、分类/标签选项和详情媒体信息；后台编辑器相关资源不进入公开首页首屏。
- 保留公开博客接口匿名访问行为，不让历史管理令牌影响公开请求。
- 对短时间内可复用的公开数据使用内存级短缓存，并在发布、登录状态变化和显式刷新时失效。

### 3. 图片与视频

- 非首屏图片默认 `loading="lazy"`、`decoding="async"`；首屏主视觉保留高优先级加载。
- 图片列表使用尺寸约束，避免加载后造成布局跳动；失败时保留现有默认图回退。
- 视频默认不自动下载，使用封面和 `preload="metadata"` 或 `none`；进入可视区域或用户主动播放时再加载。
- 不改变 iPhone 视频、HEVC/HEIF 和实况图片的既有上传业务；如浏览器不支持源格式，继续由现有后端转码/回退链路处理。

### 4. Nginx 与发布

- 对文本资源启用 gzip；若服务器已安装 Brotli 模块则仅在模块可用时启用，不把部署绑定到额外模块。
- `/assets/` 使用 immutable 长缓存和严格文件存在检查；HTML、接口和媒体资源沿用各自的安全缓存策略。
- 发布脚本先上传并校验新版本，再原子切换 current，最后执行 Nginx 配置检查和 reload。
- 保留上一版发布目录，出现异常时可通过 current 软链接快速回滚。

## 验证方案

### 自动化

- 两个前端项目的现有单元测试全部通过。
- 生产构建成功，检查最大 JS/CSS chunk、总 gzip 体积和资源命名。
- 新增针对请求去重、媒体加载属性、路由预加载行为和 Nginx 配置的测试。

### 浏览器与线上

- 使用 Chrome CDP 记录博客首页、文章详情和管理后台仪表盘的资源瀑布流。
- 验证首页不下载后台编辑器 chunk，详情页按需加载媒体，重复导航不产生重复 GET 请求。
- 验证“管理后台”入口、登录、仪表盘、动态列表和文章详情可正常打开。
- 验证新资源返回正确 MIME，旧 hash 返回 404，HTML 可获取，公开 API 在无 Token 和过期 Token 情况下均正常。
- 记录优化前后首屏请求数、传输字节数、最大内容绘制和加载完成时间，作为发布结果依据。

## 风险与回滚

- 拆包策略可能改变 chunk 依赖关系；通过生产构建和强制刷新验证，发现动态导入异常时回滚前端发布目录。
- 请求去重可能掩盖需要强制刷新的场景；显式刷新、登录切换和发布操作会清理短缓存。
- 长缓存可能让客户端保留旧 HTML；HTML 不使用 immutable，并保留动态 chunk 失败后的单次自动恢复。
- Nginx 压缩配置若测试失败，不影响代码发布；回退到仅使用现有静态资源缓存规则。
