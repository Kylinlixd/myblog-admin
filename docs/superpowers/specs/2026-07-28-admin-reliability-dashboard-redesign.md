# 管理后台可靠性与宽屏运营台重构规格

## 背景与目标

本轮同时处理管理后台的可靠性和全站视觉问题：修复发布动态、上传媒体时被误判为登录失效的问题；避免临时网络故障清空登录态；重构仪表盘在 Edge/Chromium 与台式机宽屏下的层级、密度和可读性；提升博客评论、文章阅读与全局加载反馈的辨识度。

设计与实现遵循最小改动原则：认证由共享请求层统一负责，仪表盘只使用现有 `/api/stats/` 数据，不增加依赖、不扩展后端接口。

## 已确认根因

1. 动态编辑页提交前读取旧键 `accessToken`，而当前会话使用 `blog.accessToken`，因此正常登录也会被判定为过期并跳转登录页。
2. 上传工具重复创建 Axios 实例并读取同一个旧键，导致编辑器媒体上传具有相同故障。
3. 刷新令牌失败时，共享请求层只清理 localStorage；Pinia 内存中的令牌仍为真，登录页守卫可能再次把用户送回后台。
4. 用户仓库初始化时把网络错误和服务端错误都当作认证失败，会在临时故障时不必要地注销用户。

## 方案选择

### 方案 A：内容运营台（采用）

使用非对称宽屏布局：顶部编辑式概览、紧凑指标带、主趋势画布和侧栏内容脉络。单一夜蓝强调色贯穿页面，以排版、留白和真实数据建立层级。

优点是视觉变化明显，能充分使用 1440–1920px 桌面空间，同时无需新增接口；响应式降级也清晰。

### 方案 B：高密度分析驾驶舱

增加更多图表、筛选和周期对比。它需要扩展后端统计口径并引入更多交互状态，不适合本轮可靠性优先的目标。

### 方案 C：保留现有结构做样式微调

风险最低，但四张等宽卡片和重复数据区仍会让宽屏显得空泛，无法解决用户反馈的“视觉上没有改变”。

## 认证与发布修复

- 删除动态提交前的手动 token 判断，路由守卫和共享 HTTP 拦截器是唯一认证边界。
- 将上传工具改为现有 `api/file.uploadFile` 的薄封装，保留文件类型/大小校验，删除重复 Axios、旧 token 和重复消息提示。
- `auth:expired` 事件先清空 Pinia 会话，再进入登录页，避免内存状态与 localStorage 不一致。
- 初始化用户信息失败时只在确认 `401` 后清理会话；网络错误和 `5xx` 保留本地会话，让页面按正常错误态处理。
- 为上述路径增加回归测试，覆盖旧 token 读取、认证过期清理和临时错误保留会话。

## 仪表盘信息架构

1. **运营概览**：日期、管理员称呼、内容总量与主要“新建内容”动作。深夜蓝底作为唯一强视觉区域，但减少装饰性渐变和胶囊元素。
2. **指标带**：动态、分类、标签、评论改为同一连续区域中的四个紧凑分段；使用等宽数字和细分隔线，不再做四张同权重卡片。
3. **发布节奏**：七日趋势作为主画布，保留总量、日均、峰值，并提高宽屏图表占比；峰值也使用同一蓝色层级，不引入额外彩虹色。
4. **内容脉络**：使用接口已有的分类和标签发布数量，展示真实活跃分类/标签；没有数据时提供明确空状态。
5. **快捷动作**：改为紧凑的文本行，降低卡片感，保留清晰的悬停、键盘焦点和触控反馈。

## 宽屏与 Edge 适配

- 页面有效宽度提高到约 1600px，并在 1440px、1920px 桌面显示器上保持合理密度。
- 使用标准 CSS Grid、Flex、`clamp()` 和渐进式视觉效果；核心布局不依赖 `subgrid`、遮罩或仅 Safari 可用的能力。
- 宽屏采用主区约 9/12、侧栏约 3/12；中屏改为上下布局，移动端单列。
- 所有数字使用 `font-variant-numeric: tabular-nums`，按钮最小触控高度 44px，提供 `:focus-visible` 与 reduced-motion 兼容。
- 半透明效果均有不透明背景作为回退，保证 Edge/Chromium 与普通显示器对比度。

## 字体、阅读与评论可读性

- 全站字体栈统一为 `Geist / Segoe UI / PingFang SC / Microsoft YaHei` 的系统友好组合，不请求新的网络字体；中文正文优先使用系统中文字体，避免西文字体影响汉字排印。
- 提高暗色博客的正文层级：辅助文字继续使用柔和蓝灰，文章正文与评论正文使用更明亮的独立阅读色，不再被全局 `.markdown-body` 柔化规则覆盖。
- 文章详情采用约 720–760px 的舒适行宽、18px 正文字号和约 1.9 行高；标题、段落、列表、引用、链接与代码块形成明确节奏，让正文成为页面的第一视觉焦点。
- 评论表单的标签、输入值、占位符、字数提示和评论内容分别设置可辨识色阶；评论项增加稳定间距和弱分隔，昵称与时间不争夺正文注意力。
- 动态列表继续适合快速浏览，文章详情则针对长阅读单独优化，不用一套字号强行覆盖两个场景。

## 右下角加载反馈

- 保留现有全局加载机制，重绘为轻量“状态灯 + 文案”的浮动提示，提供不透明深/浅背景回退和更清楚的边界。
- 浮层出现和离开使用短距离位移动效；加载图标改为双层轨道并减少视觉噪声。
- 在移动端避开底部安全区并限制最大宽度；`prefers-reduced-motion` 下关闭旋转和位移，仅保留静态状态。

## 错误、加载与空状态

- 仪表盘请求失败保留错误提示和重试入口，不展示伪造数据。
- 初次加载使用与最终布局形状接近的骨架，避免大幅布局跳动。
- 七日趋势、分类和标签分别拥有独立空状态，不因一个数据集合为空隐藏其他有效信息。

## 验收标准

1. 正常登录后发布动态不会因旧 token 键而跳转登录页，媒体上传走统一请求层。
2. 刷新令牌确认失效后内存与持久化会话同时清除；临时网络/服务端错误不主动注销。
3. 仪表盘使用现有真实数据完成运营概览、指标带、七日趋势、内容脉络与快捷动作。
4. 评论区的标签、输入、正文和时间信息在暗色主题中清晰可辨；文章正文对比度、行宽、字号与行高适合持续阅读。
5. 右下角加载提示在桌面和移动端位置稳定、文案清楚，并尊重 reduced-motion。
6. 1920×1080、1440×900 和移动端布局无横向溢出，Edge/Chromium 下层级清楚、文字与控件可读。
7. 不增加运行时依赖，不修改后端接口；相关单元测试、完整前端测试和生产构建通过。
