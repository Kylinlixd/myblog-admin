# 首页大屏与动态详情可靠性设计

## 目标

修复两个线上可见问题：大屏首页内容区域被 1200px 上限限制，以及动态详情在刷新、失效 ID 或附加接口异常时被错误显示为“文章不存在”。

## 设计

### 首页布局

仅给博客首页增加宽屏容器变量，使用 `min(1480px, calc(100vw - 64px))`，不改变管理后台和其他博客页面的阅读宽度。首页首屏的最小高度和上下留白改为基于视口的流式值，保留移动端现有断点覆盖，避免大屏出现固定尺寸感。

### 动态详情数据流

详情请求是页面主数据源：成功后立即渲染正文。浏览量和评论属于非关键附加请求，使用独立失败处理并在后台执行，不得让它们把正文状态改成失败。详情响应的 404 明确表示文章不存在或已删除；网络、服务器或非预期响应显示可重试的加载失败，并在路由 ID 改变时重新拉取。

### 后端错误语义

公开动态详情对不存在或未发布的记录返回 JSON 信封和 HTTP 404；其他未预期异常继续返回 500。这样客户端、搜索引擎和监控都能区分失效资源与服务故障。

## 验收标准

1. 宽屏首页内容宽度随视口扩展，最大为 1480px，首屏不再使用固定的 760–980px 最小高度。
2. 有效动态详情直接刷新可稳定显示正文。
3. 不存在或未发布的动态返回 404，并显示“文章不存在或已被删除”。
4. 网络错误显示“文章加载失败，请稍后重试”和重试按钮；评论/浏览量接口失败不影响正文。
5. 前端 Jest、后端动态 API 测试、生产构建和线上接口检查全部通过。
