# 移动端媒体上传与网页优化设计

## 目标

优化新建动态的移动端媒体上传体验，支持 iPhone 常见视频与图片格式、以网页兼容方式展示实况图片，并在服务端压缩视频以减少网页加载体积，同时保持清晰度与原始比例。

## 已确认的产品行为

- 上传界面采用“上传状态清晰”方案：支持格式、上传进度、处理中状态、处理结果和封面预览在同一媒体卡片内展示。
- iPhone 实况图片在网页端表现为“封面图 + 可播放动态片段”，不强依赖 Apple 专属播放器。
- 新建动态默认纯文本时仍显示“上传文件”快捷入口；上传后根据文件类型自动切换到图文、音频或视频。
- 视频处理结果用于网页播放，原始视频不作为前端播放源。
- 提交信息使用中文；视频识别、压缩、封面生成等核心逻辑添加中文注释。

## 本次移动端交互修正

- 图片、音频和视频上传区在移动端实际位于 Markdown 内容编辑器之前，用户先选择媒体，再填写内容说明。
- 移动端编辑表单使用单列自然流布局，不让内容编辑器跨固定网格行，避免覆盖上传入口或造成点击无响应。
- 上传入口保留现有 Ant Design Vue 上传链路，扩大可触控区域并保持至少 48px 的触控高度；选择文件后继续复用现有类型校验、进度、转码和错误提示。
- 桌面端继续使用左侧内容、右侧设置的双栏布局；移动端只调整排列顺序和网格约束，不改变接口数据结构。

## 范围

### 前端

修改 `src/views/dynamics/DynamicEdit.vue` 与相关测试：

- 接受 MP4、MOV、M4V、WebM、HEVC 视频，以及 HEIC、HEIF、JPEG、PNG、GIF 图片。
- 媒体上传卡片在移动端单列展示，提供清晰的“上传文件”“从文件库选择”操作。
- 显示上传百分比；上传结束但后端仍在转码时显示“正在优化视频”。
- 视频预览使用后端返回的封面地址；没有封面时回退到原视频地址。
- 对不支持格式、超过大小限制、转码失败提供可读错误信息。

### 后端

修改 `/Users/leexd/blog_li`：

- 扩展上传校验，接受 MOV/M4V/HEVC 视频和 HEIC/HEIF 图片。
- 使用 FFmpeg 在临时目录完成单次处理：
  - 视频输出 H.264 + AAC MP4。
  - `yuv420p` 保证主流浏览器兼容。
  - `-movflags +faststart` 将 MP4 索引前置，支持更快起播。
  - 最大边长 1920，不放大低分辨率源文件，保持原始宽高比。
  - CRF 23、medium preset、AAC 128k，在体积和清晰度之间取平衡。
  - 从处理后的视频提取首帧 JPEG 作为封面。
- HEIC/HEIF 转成 JPEG 后再存储，避免 Chrome 等浏览器无法展示原格式。
- `UploadFile` 增加封面 URL、封面存储后端和封面存储 key 字段，序列化到动态媒体信息。
- 转码失败时删除临时文件，不写入半成品数据库记录；存储失败时执行补偿删除。
- 服务器安装并验证 `ffmpeg` 与 `ffprobe`，应用保留现有 50MB 上传限制和 330 秒 Gunicorn 超时。

## 数据流

```text
移动端选择文件
  -> 前端识别 MIME/扩展名并显示上传状态
  -> POST /api/upload/upload/
  -> 后端校验类型与大小
  -> 临时文件落盘
  -> FFmpeg 生成网页 MP4/JPEG 封面
  -> 上传处理后文件到当前存储后端
  -> 写入 UploadFile 与封面字段
  -> 返回 file_url、poster_url、content_type、file_size
  -> 前端显示封面和压缩后的媒体
```

## 兼容策略

- MOV/HEVC：服务端统一转成 H.264 MP4，前端不依赖浏览器直接解码 HEVC。
- HEIC/HEIF：服务端转 JPEG，前端通过 JPEG URL 展示。
- 实况图片：移动端可上传动态片段；后端提取首帧作为封面，网页端以带封面的 MP4 播放。
- 原始文件名保留在 `name`，处理后的存储文件使用安全扩展名和随机 key。

## 测试与验证

### 前端

- 新建纯文本动态存在快捷上传入口。
- MOV、HEIC、HEIF 扩展名被识别为正确媒体类型。
- 上传进度、处理中、失败和完成状态均有对应展示。
- 动态编辑页和博客详情页使用 `poster_url`，旧数据无封面时正常回退。

### 后端

- 上传校验覆盖 MOV/M4V/HEVC、HEIC/HEIF。
- FFmpeg 命令构造覆盖比例保持、最大尺寸、H.264/AAC、faststart 和封面提取。
- 转码失败不会残留临时文件或数据库记录。
- 上传接口返回处理后大小、类型和封面地址。

### 线上

- 在虚拟环境 `/opt/anaconda3/envs/blog` 下运行后端测试。
- 安装并验证服务器 FFmpeg/FFprobe。
- 使用一段 iPhone MOV、一个 HEIC 文件和一个普通 MP4 完成真实上传验证。
- 检查线上视频响应包含 `Content-Type: video/mp4`、可播放和 `faststart` 起播行为。

## 非目标

- 本轮不引入 Celery、Redis 或独立转码队列。
- 本轮不保存 Apple 原生 Live Photo 专属元数据；网页表现以封面加动态 MP4 为准。
- 本轮不改变已有动态、文件库和数据库历史媒体的 URL 语义。
