# myblog-admin 前端联调与体验优化设计

## 目标

在不改变 `blog_li` 后端业务逻辑、数据库结构和现有 API 语义的前提下，完成管理后台的前后端联调，并优先修复页面排版、操作反馈和移动端体验问题。

## 范围

覆盖登录、后台壳层、仪表盘、动态/文章管理、分类、标签、评论、文件、个人资料和移动端导航。公共博客页面不纳入本轮改造。

不新增状态管理、图表、动画或 UI 依赖；复用现有 Vue 3、Pinia、Vue Router、Ant Design Vue、Axios 和已有组件。

## 设计方向

采用“冷静工作台”视觉方向：深色左侧导航、明亮内容区、蓝色单一强调色、低饱和蓝灰背景和清晰的内容分区。排版以稳定的页面标题、筛选区、内容区和操作区间距为基础，避免过度装饰和复杂动画。

## 实现原则

### 1. 联调边界

- API 根地址通过 `VITE_API_BASE_URL` 配置，开发和生产环境分离。
- 继续使用现有 API 模块和请求封装，修复响应包装、分页列表、token 注入、过期刷新和上传 URL 的前端兼容问题。
- 页面不直接拼接服务器地址，不在仓库写入服务器、数据库或 SSH 密码。
- 只修复阻塞页面正常工作的接口适配，不改后端业务逻辑。

### 2. 页面排版

- 后台壳层统一侧栏、顶部栏、内容区宽度、标题层级和页面间距。
- 文章列表优先保证筛选、表格、批量操作和分页的可读性；窄屏保留横向滚动。
- 文章编辑页按标题、正文、发布设置、媒体资源分区，减少表单拥挤和重复操作。
- 分类、标签、评论、文件和个人资料沿用同一套页面标题、操作栏、状态提示和空态结构。

### 3. 交互反馈

- 列表请求显示贴合布局的加载状态，空数据提供下一步操作，失败状态提供重试。
- 按钮具备 hover、active、disabled、loading 状态；危险操作保留二次确认。
- 搜索、筛选、重置、分页、批量删除、审核、上传和保存后显示明确的成功或失败反馈。
- 保存失败时保留当前编辑内容；鉴权失效时清除会话并回到登录页。
- 移动端使用抽屉导航，优化顶部操作栏、表单栅格、弹窗宽度和媒体选择器。

## 主要改动顺序

1. 后台壳层、导航、顶部栏和全局样式。
2. 仪表盘的信息层级、数据状态和响应式布局。
3. 动态列表与编辑器的筛选、分页、媒体关联、保存和错误反馈。
4. 分类、标签、评论、文件和个人资料页面的一致性修复。
5. 统一检查接口地址、静态资源路径、移动端布局和生产构建。

## 验收标准

- `npm run test:ci` 通过。
- `npm run build` 通过。
- 登录、登出、鉴权失效、仪表盘加载可用。
- 文章列表筛选、重置、分页、批量删除可用。
- 文章新建/编辑、草稿保存、发布、媒体上传或文件库选择可用。
- 分类、标签创建/编辑/删除可用。
- 评论审核、文件管理、资料修改可用。
- 主要页面在桌面和移动宽度下无明显溢出、遮挡或不可操作控件。
- 服务器部署目录中的前端资源和 API 地址与本地构建结果一致。

## 不做的事情

- 不重写后端。
- 不改数据库模型或迁移。
- 不新增富文本编辑器、全局数据请求库、图表库或大型动画方案。
- 不在本轮扩展公共博客页面功能。
