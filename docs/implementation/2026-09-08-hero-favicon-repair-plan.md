### 标题与验收问题

- 桌面 Canvas 字形按估计字号/宽度/坐标及 750 字重绘制，DOM 标题则使用 800 字重、负字距、flex gap 和自己的盒模型，两套字形不精确重合。
- Canvas 在 titleReady 时立即消失，实体字才开始 1.4 秒渐显；属于两个独立时间线，不能保证平滑交接。
- 当前手机分支直接禁用了标题粒子，450ms 后显示实体字，是降级而非修复了粒子聚合。
- `BlogHomeExperience.spec.js` 的 5 项测试是源码字符串断言，不能证明标题不裁切、背景好看、鼠标跟随可见或 Safari 正常。
- 上轮 headless 截图出现右侧内容裁切，未记录实际 innerWidth/visualViewport，也未完成最后调整后的同尺寸截图。仅 `--window-size=390,844` 不能替代真实设备模拟；上轮“手机完整适配”的结论缺少充分证据。

## 2. 给 Luna 的实施范围

保留暖米色调、居中单行标题、标题文案/配色、现有导航结构、滚动箭头和文章区。仅修 favicon、Hero 背景、必要的移动端尺寸与动画问题。不要重新设计整站，不加第三方动画/UI/图标库，不新增图片背景，不重新配置 SSH。

保留现有未关联改动：`.gitignore`、`content/`、`design/`、`public/articles/`、`BlogHome 2.vue`、`BlogHomeExperience.spec 2.js`。不要删除、格式化或一起提交。开始时再次检查状态和 main；如 main 已前进，重新核对相关差异。

### A. 独立制作可读的 favicon

1. 新建 `public/favicon-coffee-v2.svg`，使用原生 SVG 手绘简化咖啡杯：保留杯体、杯柄、一缕蒸汽，移除代码吊牌及细碎装饰。
2. 采用 32×32 viewBox，图案占约 24–26px，笔画约 2.2–2.8px；深棕 `#9B4E28` 配暖奶油底 `#FFF8ED`，优先实心/粗轮廓。16px 下应仍可辨认杯子。
3. 更新 `index.html` 的 rel=icon 路径和 MIME 为新 SVG。使用新文件名使浏览器重新请求；导航继续用现有大 Logo。
4. 在真实标签页与 16/32px 两种展示尺寸检查。若目标浏览器需要 PNG fallback，再从同一简化矢量导出并明确声明尺寸，不能引用回旧淡图标。

### B. 替换背景，不再叠加旧层

推荐把背景隔离为 `src/components/blog/HeroAtmosphere.vue`，绝对定位、aria-hidden、pointer-events:none；继续使用 Vue script setup、scoped CSS 和原生 Canvas/CSS。

1. 从旧背景中移除三条大轨道、五条游离曲线、右侧散点、重复 glow-field/blob 光晕及 multiply。保留标题动画时不能误删标题 Canvas；将标题绘制与背景绘制职责分开。
2. 背景只保留三层：统一暖奶油底色；两片横跨视口的柔和光幕；极少量内嵌光纹（最多两条，不画独立“点加尾巴”）。先做好前两层，再决定是否需要第三层。
3. 构图用左上约 (28%,36%) 和右下约 (70%,62%) 两个面积相近的光幕，中央标题区保持清晰；右侧只略重。移动端改成约 (35%,30%) 和 (65%,70%)，不要直接压缩桌面构图。
4. 底色建议 `#F6EFE4`，暖杏建议 `#E4C7A5`，灰绿只作非常轻的辅助（建议低于 6% alpha），去掉棕绿相乘与大面积暗角。起始强度需要截图调校，不以不断调低透明度作为验收。
5. 如选 Canvas，用离屏低分辨率缓冲层（DPR 不超过 1–1.5）画柔光，整层柔化后合成；若用 CSS，固定 blur，只动画 transform/opacity，避免每帧修改 filter、border-radius、渐变位置。两者择一作为光幕实现，避免再次同时堆叠。
6. 背景边缘回归布局底色，检查顶边和左右边缘无矩形硬切；通过背景层处理，不改导航尺寸。

### C. 做可感知且克制的动态

1. 呼吸完整周期从 20–28 秒起调，位移从画面尺度的 1%–2% 起调，颜色保持低饱和。JS 使用 `2 * Math.PI * elapsed / periodMs` 明确表达周期。
2. 桌面鼠标左右移动时两层产生不同深度的平滑位移，从 ±20px、±35px 起调；以约 180–300ms 时间常数插值，速度不依赖刷新率。标题和箭头不随背景移动，离开 Hero 平缓回中。
3. 触屏默认自主呼吸，滚动不被拦截，不设置 touch-action:none。不要承诺手机有桌面 hover 行为。
4. Hero 离屏、页面隐藏时暂停绘制，恢复时不跳帧；prefers-reduced-motion 下给出稳定静态背景，不继续跑无意义 RAF。卸载时清理事件、Observer 和 RAF。

### D. 修复移动端尺寸和标题交接

1. 移除 Home 对 header-height 的冲突覆写，使用布局的同一变量。首屏高度用动态视口减实际导航占位，纳入 Safari 地址栏变化和箭头安全间距。
2. compactScreen 根据实际 Hero 宽度更新，或监听 matchMedia change；普通高度 resize 不应重新播放标题。
3. 根据真实可用内容宽度选标题字号，保留一行；避免用过大的负字距硬挤。断点和字体设置需要 320/375/390/430px 实测。
4. 桌面聚合标题若仍保留，按 DOM 每段标题的实际 rect、computed font、letterSpacing 采样；等待字体就绪，一条时间线完成粒子与实体字交接，完成后释放标题粒子绘制。不要再用 fontSize*8.8 估算位置。
5. 手机本次可保留平稳淡入的低成本降级并在交付中说明，禁止重新加入错位点阵以满足源码字符串测试。
